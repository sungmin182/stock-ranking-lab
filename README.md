# 주식 랭킹 랩

KRX·DART 공개 데이터를 **내가 정한 기준으로 다시 정렬**하는 국내 주식 비교 도구.
빌드 도구 없이 정적 파일로 돌아간다. 자매 프로젝트 “보드게임 랭킹 랩”과 같은 구조다.

```
npm run sample  # 키 없이 화면부터 보기 (지어낸 예시 420종목)
npm run sync    # 진짜 데이터 수집 → data/stocks.json
npm run dev     # http://localhost:4174
```

> **투자 조언이 아닙니다.** 이 도구는 공개된 공시·시세 자료를 정리해 비교할 뿐이고,
> 어떤 종목도 추천하지 않습니다. 값이 틀릴 수 있으며 투자 판단과 결과는 본인의 몫입니다.
> 화면 맨 위에도 같은 문구가 항상 떠 있습니다.

## 1. 데이터가 어디서 오는가

세 곳을 실제로 찔러 보고 정했다.

| 무엇 | 출처 | 인증 | 갱신 |
| --- | --- | --- | --- |
| 전종목 시세·시가총액·상장주식수 | **KRX 오픈API** `data-dbg.krx.co.kr/svc/apis/sto` | 헤더 `AUTH_KEY` (무료) | 장 마감 후 |
| 종목기본정보(상장일·우선주 여부) | 같은 곳 `stk_isu_base_info` 등 | 같음 | 수시 |
| 재무제표·배당 | **DART 오픈API** `opendart.fss.or.kr` | 질의 `crtfc_key` (무료) | 분기 |

### 키 없이 긁는 길은 없다 (재봤다)

KRX 정보데이터시스템(`data.krx.co.kr`)의 내부 JSON 엔드포인트는 예전엔 키 없이
열렸지만 지금은 막혀 있다. 추측이 아니라 직접 눌러 본 결과다.

| 시험 | 결과 |
| --- | --- |
| `getJsonData.cmd` — 그냥 POST | `400 LOGOUT` |
| 로더 페이지에서 `JSESSIONID` 받아 붙임 | `400 LOGOUT` |
| `X-Requested-With`·`Referer`까지 정확히 붙임 | `400 LOGOUT` |
| CSV 내려받기용 `GenerateOTP.cmd` | 에러 페이지 |
| `http` / `https` 양쪽 | 둘 다 같음 |

BGG 때와는 반대 상황이다. 대신 **공식 API 세 개가 전부 무료**라 조건은 오히려 낫다.
셋 다 살아 있는 것을 확인했다 — 키 없이 부르면 `401 Unauthorized Key`,
`403 등록되지 않은 서비스키`, `{"status":"010"}` 이 각각 돌아온다.

### 키 발급 (각 5분, 무료)

1. **KRX** — <https://openapi.krx.co.kr> 가입 → 인증키 발급
2. **DART** — <https://opendart.fss.or.kr> 가입 → 인증키 발급

```powershell
$env:KRX_API_KEY  = "발급받은키"
$env:DART_API_KEY = "발급받은키"
npm run sync
```

GitHub Actions 로 매일 돌릴 때는 저장소 `Settings → Secrets and variables → Actions`
에 같은 이름으로 넣는다.

#### KRX 401 은 두 가지 뜻이다

키를 넣었는데도 401 이 나면 **응답 메시지를 봐야 한다.** KRX 는 인증키 발급과
**API 별 사용 승인이 따로**라서, 키가 살아 있어도 그 API 를 부를 권한이 없으면
똑같이 401 이 온다. 여기서 한참 헤맸다.

| 응답 | 뜻 | 할 일 |
| --- | --- | --- |
| `Unauthorized Key` | 키가 없거나 틀렸다 | `KRX_API_KEY` 값 확인 |
| `Unauthorized API Call` | 키는 맞는데 이 API 권한이 없다 | openapi.krx.co.kr 에서 해당 서비스 사용 신청·승인 확인 |

필요한 서비스는 `유가증권 일별매매정보`, `코스닥 일별매매정보`, `종목기본정보` 다.
`sync-prices.mjs` 가 둘을 구별해 한 줄로 알려 주고, **시장 하나가 막혀도 나머지는
받는다** — 코스피만 승인되고 코넥스는 아직인 상태가 실제로 생기기 때문이다.
하나도 못 받았을 때만 실패한다.

### 키를 넣기 전에

`npm run sample` 이 같은 모양의 파일을 하나 만들어 준다. **실재하지 않는 회사와
지어낸 숫자**다. 실제 상장사 이름에 가짜 재무를 붙이면 화면을 캡처해 옮기는
순간 거짓 정보가 되기 때문에, 회사 이름부터 지어냈고 종목코드도 `9`로 시작한다.
예시로 도는 동안에는 화면 위에 빨간 띠가 뜬다.

## 2. PER·PBR·ROE 를 직접 계산한다

KRX 오픈API 는 **시세와 시가총액까지만** 준다. 밸류에이션 지표는 재무제표가 있어야
나오는 값이라, DART 에서 원자료를 받아 `scripts/build.mjs` 에서 엮는다.

```
PER      = 시가총액 ÷ 당기순이익
PBR      = 시가총액 ÷ 자본총계
PSR      = 시가총액 ÷ 매출액
ROE      = 당기순이익 ÷ 자본총계
영업이익률 = 영업이익 ÷ 매출액
부채비율   = 부채총계 ÷ 자본총계
배당수익률 = 주당 현금배당금 ÷ 현재가
배당성향   = (주당배당금 × 상장주식수) ÷ 당기순이익
```

어디선가 받아온 숫자가 아니라 공시 원자료에서 계산한 값이라서, **상세 패널에
계산식을 그대로 적어 두었다.** 왜 이 PER 이 나왔는지 화면에서 바로 확인된다.

몇 가지 판단이 들어가 있다.

- **적자면 PER 을 비워 둔다.** 순이익이 음수면 PER 도 음수가 되는데 "PER 이 낮아서
  싸다"는 해석이 통하지 않는다. 표에는 `적자`로 나온다.
- **연결(CFS)을 우선한다.** 지주회사나 해외 자회사가 큰 기업은 개별 재무만 보면
  실제 규모와 크게 어긋난다. 연결이 없으면 개별을 쓴다.
- **적자에서 적자로 간 것은 증가율을 계산하지 않는다.** −100억에서 −50억이 된 것을
  "+50% 성장"이라 부를 수는 없다. 부호가 바뀌는 구간에서 증가율은 뜻을 잃는다.
- **수익률은 수정주가가 아니다.** 액면분할·유상증자를 보정하지 않은 단순 종가
  비교다. 그런 일이 있었던 종목은 기간 수익률이 실제와 다르다. 상세 패널에도
  그렇게 적어 두었다.
- **믿기 어려운 배당률에는 표시를 단다.** 주당배당금은 1년 전 사업보고서 값인데
  주가는 최근 종가다. 그 사이 액면분할·무상증자·특별배당이 끼면 비율이 깨진다.
  전체 분포는 중앙값 2.5% · 90퍼센타일 6% 인데 아홉 종목만 19~42%로 튀어
  하필 `배당주` 정렬의 맨 위를 차지했다. **배당률 15% 초과**면 `⚠ 확인 필요`
  표시를 달고 **점수 축에서만** 뺀다 — 공시에서 나온 값이라 감추지는 않는다.

  처음에는 `배당성향 200% 초과`도 함께 걸었더니 39종목이 잡혔다. 두산밥캣
  (배당률 2.78%)처럼 **배당률 자체는 멀쩡한** 종목이 대부분이었다. 그해 순이익이
  쪼그라들면 배당성향만 치솟기 때문인데, 그건 배당률이 틀렸다는 신호가 아니라
  그해 이익이 나빴다는 신호다. 그래서 "이 배당률을 믿을 수 있나"만 본다.

### 과거 스냅샷

"최근 3개월 수익률" 을 쓰려면 그 시점 종가가 필요한데 일별매매정보 API 는 하루치만
준다. 그래서 오늘·30일 전·90일 전·365일 전 네 날짜를 각각 받아 `cache/prices` 에
쌓아 둔다. 과거 날짜 값은 바뀌지 않으므로 한 번 받으면 다시 받지 않는다.
휴장일이면 값이 빈 배열로 오므로 하루씩 물러나며 거래일을 찾는다(최대 10일 —
설·추석 연휴가 닷새까지 간다).

## 3. 나만의 랭킹 점수

이 사이트의 핵심. 정렬 기준을 고르는 게 아니라 **점수식을 직접 만든다.**

10개 축에 −100 ~ +100 가중치를 주면

```
점수 = Σ (가중치 / 100) × 백분위(축)
```

로 계산해 실시간 재정렬한다. 각 축은 원시값이 아니라 **전체 종목 중 백분위**로
환산해서 쓴다. PER 8배와 ROE 14%와 시가총액 3조는 단위가 달라 그대로 더할 수 없고,
백분위는 시총 400조짜리 한 종목에 결과가 끌려가지 않기 때문이다.

| 축 | 의미 | 음수로 두면 |
| --- | --- | --- |
| 저PER | 이익 대비 싼가 | 비싼 종목 우선 |
| 저PBR | 순자산 대비 싼가 | 비싼 종목 우선 |
| 수익성 | ROE | 못 버는 회사 |
| 배당 | 배당수익률 | 배당 안 주는 회사 |
| 안정성 | 부채비율 낮을수록 | 빚 많은 회사 |
| 성장성 | 매출 증가율 | 역성장 |
| 모멘텀 | 최근 3개월 수익률 | 많이 빠진 종목 |
| 규모 | 시가총액(로그) | **소형주 발굴** |
| 거래활발 | 거래대금(로그) | 거래가 적은 종목 |
| 내 평가 | 내가 매긴 점수 | — |

PER·PBR 은 로그를 씌운 뒤 부호를 뒤집는다. PER 5와 10의 차이가 100과 105의 차이보다
크기 때문이다. 값이 없는 종목(신규 상장·리츠·스팩)은 중앙값으로 쳐서 점수가
과하게 깎이지 않게 한다.

프리셋 9종(`시총순`, `가치주`, `배당주`, `우량 대형`, `소형 발굴`, `성장주`,
`모멘텀`, `퀄리티`, `내 평가순`)이 출발점으로 들어 있다.
새 프리셋은 `assets/app.js` 의 `PRESETS` 에 한 줄 넣으면 된다.

**모든 상태는 URL에 담긴다.** 가중치·필터·정렬을 맞춘 뒤 `링크 복사`를 누르면
그 화면 그대로 열리는 주소가 나온다.

> 새 축을 추가할 때는 반드시 `mine` 앞까지만 끼워 넣는다. URL 의 `w` 파라미터가
> `AXES` 순서대로 직렬화되므로, 중간에 넣으면 예전에 공유한 링크의 가중치가
> 한 칸씩 밀린다.

## 4. 기능

- **필터** — 시장, 시가총액, PER, PBR, ROE, 배당수익률, 부채비율, 주가, 업종,
  적자 제외, 배당 주는 것만, 우선주 제외(기본 켜짐), 3개월 상승, 내 목록만.
  자주 쓰는 구간은 `10 이하` `1조↑` `ROE 15%↑` 처럼 칩으로 바로 집을 수 있다.
  업종은 클릭할 때마다 포함 → 제외 → 해제 3단계다.
- **화면 배치** — 넓은 화면(1180px 이상)에서는 점수·필터가 왼쪽 사이드바로 가고
  결과 표가 오른쪽에 항상 떠 있다. 사이드바는 따로 스크롤되므로 가중치를 만지는
  동안 표가 눈에서 사라지지 않는다. `☰`로 접으면 표가 화면 전체 폭을 쓴다.
- **패널 접기** — 점수·필터 패널은 제목의 `▾`로 접는다(상태는 기억된다).
  접어도 **프리셋 버튼은 그대로 남고**, 제목 옆에 `· 배당주`나
  `· 직접 조절 (저PER +65, 저PBR +55, …)` 같은 한 줄 요약이 붙는다.
- **표시를 눌러도 목록이 흔들리지 않는다** — 관심·보유 같은 표시는 대개 그 줄의
  아이콘 색만 바뀌므로, 목록을 다시 만들지 않고 그 줄만 다시 칠한다.
  걸려 있는 필터가 표시를 보고 있을 때만 전체를 다시 만든다.
- **슬라이더는 프레임당 한 번만 다시 그린다.** 끄는 동안 `input` 이 초당 수십 번
  나오는데 묶지 않으면 하나도 못 따라간다. 숫자 표시는 즉시 바꿔 손끝 반응은 유지한다.
- **표 / 카드** — 값을 비교할 때는 표, 훑어볼 때는 카드. 오른쪽 위에서 전환하고
  선택은 기억된다. 둘 다 스크롤하면 80개씩 이어서 불러온다.
- **표** — 16개 컬럼 정렬, 간결 모드, CSV 내보내기(엑셀에서 종목코드 앞의 0이
  떨어지지 않게 글자로 감싸고 BOM 을 붙인다).
- **상세 패널** — 시세·**주가 차트**·기간 수익률 막대·투자 지표(계산식 포함)·
  재무 원자료·내 기록·바깥 사이트 바로가기. 왼쪽 모서리를 끌어 폭을 조절할 수
  있다(기억되며, 더블클릭하면 기본값). `Esc` 로 닫힌다.
- **주가 차트** — 6개월 / 1년 / 3년 / 5년 구간을 고른다(선택은 기억된다).
  마우스를 올리면 그 시점의 날짜·종가·구간 시작 대비 등락이 뜬다.
  세로축은 그 구간의 최저~최고에 맞춰 늘린다 — 0부터 그리면 대부분의 종목이
  화면 위쪽에 눌린 직선으로 보이기 때문이다. 선 색은 한국 관례대로
  오르면 빨강, 내리면 파랑이다.

  자료는 `data/history.json` 에 따로 있고 **상세 패널을 처음 열 때 받는다.**
  1MB 남짓이라 첫 화면에서 같이 받으면 표가 뜨는 게 늦어진다.
- **기간 수익률** — 1일 · 7일 · 1개월 · 3개월 · 6개월 · 1년 · 5년.
  1일은 KRX 가 주는 당일 등락률을 그대로 쓴다(전 거래일을 따로 받을 이유가 없다).
  막대 폭은 기간마다 다르게 잡았다 — 하나로 두면 1일 막대는 늘 붙어 있고
  5년 막대는 늘 끝까지 찬다.
- **주식 용어** — 지표 이름에 점선 밑줄이 붙고 누르면 뜻이 뜬다. 표 머리글은
  마우스만 올려도 한 줄 설명이 나온다. 결과 패널의 `주식 용어` 로 23개 항목을
  한 화면에서 볼 수도 있다.

  각 항목은 **한 줄 정의 · 계산식 · 어떻게 읽나 · 이것만 보면 틀리는 곳**으로
  되어 있고, 마지막 것이 핵심이다. "PER 이 낮아서 싼 게 아니라 앞으로 못 벌
  것 같아서 낮은 경우가 많다", "은행 부채비율 1,000%는 정상이다" 같은 것들이다.
  무엇을 사고팔지는 말하지 않는다.
- **비교 뷰** — 행의 `⇄` 로 최대 4개까지 담아 20개 항목을 나란히 놓는다.
  더 나은 값에 색을 넣는다(PER·PBR·부채비율은 낮은 쪽, 나머지는 높은 쪽).
  전부 같으면 강조하지 않는다.

### 내 기록

종목마다 **내 평가(별 다섯 개, 반 칸이 1점), 보유 수량, 평균 매수가, 목표가, 메모**를
적는다. 적기만 하면 나머지는 계산된다.

| 나오는 값 | 계산 |
| --- | --- |
| 매수 금액 | 수량 × 평단 |
| 평가 금액 | 수량 × 현재가 |
| 평가 손익 / 수익률 | 평가 − 매수 |
| 목표가 대비 | (현재가 − 목표가) ÷ 목표가 |

**거래 기록**(날짜·매수/매도·수량·단가)을 남기면 `평단 56,667원 · 15주로 채우기`
버튼이 생겨 수량과 평단을 계산해 넣어 준다. 매도는 평단을 그대로 두고 수량만
줄이는 이동평균법이다. 실현손익까지 따지려면 수수료·세금이 필요한데 그건 이 도구가
알 수 없는 값이라 넣지 않았다.

수량·평단을 **직접 적는 쪽이 원본**이고 거래 기록은 계산해서 채워 주는 보조다.
두 곳이 조용히 어긋나는 것보다 낫다.

**내 평가는 점수 슬라이더의 축으로도 들어간다.** 프리셋 `내 평가순`이 그 예다.
표에는 `내 평가 · 보유 · 평가손익` 열이 붙는다(기록이 하나라도 생기면 자동으로 켜진다).

### 내 포트폴리오

결과 패널의 `내 포트폴리오` 버튼. **표의 표시 버튼과 그대로 이어진다.**
● 를 누른 종목이 `보유 중`, ★ 가 `관심`, ○ 가 `매도한 종목`에 쌓인다.

- 총 매수금액 · 평가금액 · 평가손익 · 수익률
- 종목별 비중 막대
- **업종 분산** — 한 업종에 몰려 있는지 한눈에 보인다
- 관심 종목은 **목표가에 가까운 순**으로 정렬되고, 도달하면 `도달` 표시가 붙는다

기록은 이 브라우저에만 있다. `백업 내보내기`로 JSON을 받고 `가져오기`로 되돌린다.
가져오기는 **덮어쓰지 않고 종목 단위로 합치며**, 겹치는 것이 있으면 먼저 물어본다.
다른 기기에서 적은 것을 합칠 때 한쪽이 사라지면 안 되기 때문이다.

## 5. 배포

`.github/workflows/sync.yml` 이 평일 저녁(10:00 UTC = 19:00 KST)에 돌아
데이터를 새로 받고 GitHub Pages 로 배포한다.

- 과거 시세와 재무제표는 `actions/cache` 로 재사용한다. 매일 처음부터 다시 받으면
  DART 하루 한도(20,000건)를 2,600종목 배당 조회로 금방 쓴다.
- **수집이 실패해도 배포는 한다.** 수집 단계가 죽으면 워크플로가 통째로 멈춰
  사이트가 404 로 남는다. 그래서 두 수집 단계 모두 `continue-on-error` 로 두고,
  `build.mjs` 가 기존 `data/stocks.json` 을 그대로 내보낸다(없으면 저장소에
  커밋된 예시 자료가 그 자리에 있다). 재무만 실패하면 PER·PBR·ROE 칸이 비고
  시세는 그대로 나온다.
- **대신 실행은 빨갛게 남긴다.** 맨 뒤의 `report` 잡이 배포가 끝난 뒤 시세 수집
  결과를 보고 실패했으면 종료 코드 1을 낸다. 이게 없으면 초록 뱃지 뒤에서
  자료가 몇 달째 늙는데 아무도 모르는 상태가 된다. 무엇이 실패했고 무엇이
  배포됐는지는 실행 페이지의 `Summary` 에 표로 찍힌다.
- 배포마다 자산 주소에 `?v=<run_id>` 를 붙인다. GitHub Pages 가 자산에
  `max-age=600` 을 주기 때문에, 안 붙이면 새 `index.html` 과 캐시된 옛 `app.js` 가
  10분쯤 섞인다. `app.js` 는 자기 주소의 `?v=` 를 읽어 데이터 주소에도 같은 번호를
  붙인다 — 자산에만 붙이고 데이터에 안 붙이면 새 코드가 캐시된 옛 데이터를 읽는다.

저장소 `Settings → Pages → Source` 를 **GitHub Actions** 로 두고,
`Secrets` 에 `KRX_API_KEY` · `DART_API_KEY` 를 넣으면 된다.

## 6. 파일

```
index.html            화면 뼈대
assets/
  config.js           바깥 사이트 주소, 중계 서버 주소
  style.css           라이트/다크 두 벌
  app.js              점수·필터·표·상세·포트폴리오 전부
scripts/
  lib.mjs             HTTP 재시도, ZIP 풀기, 동시성
  sync-prices.mjs     KRX 오픈API → data/prices.json
  sync-financials.mjs DART 오픈API → data/financials.json
  build.mjs           둘을 엮어 → data/stocks.json  ← 화면이 읽는 유일한 파일
  make-sample.mjs     키 없이 볼 예시 데이터
  serve.mjs           의존성 없는 로컬 서버
data/                 stocks.json (배포 대상), prices/financials.json (중간 파일)
cache/                날짜별 시세, DART 재무 (git 에 올리지 않음)
```

의존성은 **없다.** `npm install` 도 필요 없다.

DART 고유번호 목록이 zip 으로만 나오는데, 그것 하나 때문에 패키지를 늘리고 싶지
않아 `lib.mjs` 의 `unzipFirst` 로 직접 푼다 — ZIP 로컬 헤더는 구조가 단순하고
압축 방식도 deflate 아니면 무압축뿐이라 `node:zlib` 로 충분하다.

## 7. 아직 안 한 것

- **실시간 시세** — KRX 오픈API 는 헤더에 인증키를 요구하는데, 브라우저에서 직접
  부르면 그 키가 개발자도구에 그대로 드러난다. 공개 저장소에 올라가는 사이트에서는
  하면 안 된다. 키를 대신 들고 있는 Cloudflare Worker 를 하나 두고
  `assets/config.js` 의 `LIVE_PROXY` 에 주소를 적으면 붙일 수 있다.
- **기기 간 동기화** — 보드게임 쪽에 있는 암호화 + KV 동기화. 위 Worker 와 같은
  곳에 얹으면 된다. 지금은 JSON 백업 내보내기/가져오기로 대신한다.
- **분기 재무** — 지금은 연 1회 사업보고서만 본다. 8월에 보는 값이 작년 12월
  기준이라는 뜻이다. `reprt_code` 를 반기(11012)·분기(11013/11014)로 바꾸면
  최근 실적을 쓸 수 있지만, 분기 손익은 누적/개별 구분이 회사마다 달라
  그대로 더하면 틀린다. 손댈 때 주의할 것.
- **업종 분류** — KRX 가 주는 `SECT_TP_NM` 을 그대로 쓴다. 시장마다 뜻이
  조금씩 달라(코스닥은 소속부에 가깝다) 정교한 업종 비교에는 부족하다.
